## 4. Dictation accuracy, all 102 supplied clips (release-build self-test)

Normaliser: `app_core::metrics::normalise_for_scoring` (lower case, punctuation out, "50,000" =
"50000"; number words and digits are not equal). "Tolerant" also accepts the listed Roman
Hinglish spelling variants (wo/woh, to/toh, ...). Per-clip files: `ACCURACY_ENGLISH.csv`,
`ACCURACY_HINGLISH.csv` (reference, raw text, final text, route, recognition and clean-up time,
clean-up route, audio and text uploads, WER/CER per clip). Synthetic voices (Windows TTS "Heera",
"Ravi"): useful to compare versions, not a promise for real speech.

| Set | Clips / words | WER | Tolerant | CER | Notes |
|---|---|---|---|---|---|
| English | 30 / 322 | **0.62%** | 0.62% | 0.34% | same as 0.4.2/0.4.3; 2 substitutions |
| Hinglish A | 60 / 594 | **20.37%** | 17.68% | 7.02% | run 1 (before the routing fixes below) |
| Hinglish B | 12 / 132 | **31.82%** | 30.30% | 14.11% | run 1; 2 clips misrouted as English, 2 left in Hindi letters by the AI limit |
| Hinglish A + B | 72 / 726 | **22.45%** | 19.97% | 8.28% | run 1 |

For comparison, 0.4.2's app route measured 20.03% on set A and 24.24% on set B (17-18 Nov).
**Set B is worse in run 1**, for two reasons found in the per-clip results and fixed:
1. Misspelt Hinglish from the no-fixed-language request ("Kal meeting 4 bajay hay") passed as
   plain English. Fix: the Hindi-mode answer for the same audio and the local language check on
   the graphics card must both agree before an answer is treated as English.
2. Groq's free daily token limit for the clean-up model (200,000 tokens; one dictation uses
   about 2,000-3,000) was used up by the benchmark itself, so Hindi-letter answers could not be
   converted. Fixes: fall back to the next Groq model (own daily allowance), and use the Roman
   answer of the parallel request instead of Hindi letters.

**After the fixes**, measured only on the 6 set-B clips of one voice (the daily limit was used
up, which also exercised the fallback): **30.30% -> 21.21%** WER (66 words; tolerant 27.27% ->
18.18%). "Kal meeting chaar baje hai, please time pe aa jana." now comes out exactly.
**Not run:** the full 72-clip Hinglish run after the fixes - Groq's free daily allowance was
used up; to be run when it has recovered.

Speed (run 1, from the CSV files): recognition median 497 ms for English (90th percentile 1,116 ms)
and 1,289 ms for Hinglish (90th percentile 2,814 ms, which includes the AI conversion to Roman
letters); clean-up median 369 ms / 487 ms. Clips are 4-10 s long; two Groq requests run in
parallel in English + Hinglish mode. Uploads per
dictation: 2 audio (3 when English parts are re-checked) and 1-3 text.
